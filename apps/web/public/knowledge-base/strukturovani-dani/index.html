Як перевірити структуровані дані на сторінці

Знайти JSON-LD, зіставити його з видимим контентом і перевірити синтаксис та підтримуваний тип.

Опубліковано й перевірено: 20 жовтня 2026

Структуровані дані описують контент у машинному форматі. Вони повинні відповідати сторінці, яку бачить людина. Синтаксично коректний JSON-LD із вигаданими відгуками, авторами чи цінами залишається неправдивим описом.

У цьому матеріалі

  • Підготуйте сторінку та правильний тип
  • Знайдіть розмітку й перевірте дані
  • Використайте два види перевірки
  • Приклад із датами статті
  • Якщо тест і звіт розходяться

Підготуйте сторінку та правильний тип

Оберіть реальний товар, статтю або сторінку з навігаційним ланцюжком. Для знахідок SEO потрібен Basic або Complete. Визначте, що на сторінці фактично є: Article для статті, Product для товару, BreadcrumbList для видимої структури навігації.

Не додавайте тип лише заради бажаного вигляду Google. Підтримка пошукових функцій змінюється; перевіряйте актуальну документацію саме вашого типу перед реалізацією.

Знайдіть розмітку й перевірте дані

  1. Перегляньте скрипти application/ld+json у вихідному HTML.
  2. Перевірте DOM, якщо дані додає JavaScript.
  3. Зіставте назву, адресу, мову, дати й ціну з видимою сторінкою.
  4. Перевірте посилання на зображення та сутності.
  5. Знайдіть повторні блоки від CMS і плагіна, які суперечать один одному.

Якщо стаття не має названого автора, не вигадуйте Person. Якщо публікація відбулася сьогодні, не ставте стару дату, щоб імітувати історію.

Використайте два види перевірки

Schema.org Validator допомагає перевіряти словник і структуру. Google Rich Results Test перевіряє підтримувані Google типи та вимоги відповідних функцій. Відсутність певного rich result у тесті не означає, що будь-яка розмітка сторінки некоректна.

Для живого URL перевірка враховує доступність ресурсу. Для фрагмента коду можна швидко знайти помилку синтаксису, але він не доводить, що саме такий код опублікований на сайті. Після правки обовʼязково тестуйте живу адресу.

Приклад із датами статті

У CMS заголовок і дата статті правильні, але JSON-LD досі описує шаблонну публікацію. Виправте джерело генерації, щоб headline збігався з H1, URL — з canonical, а datePublished — з видимою датою. DateModified змінюйте після значущого оновлення матеріалу.

Очікуваний результат — валідна й правдива розмітка. Google не зобовʼязаний показувати розширений результат навіть за дотримання вимог. Не включайте його появу як гарантований критерій приймання роботи підрядника.

Якщо тест і звіт розходяться

Порівняйте час, вихідний HTML і відрендерений DOM. Плагін міг додавати розмітку із затримкою або лише для певної мови. Знахідка сканера потребує перевірки на актуальному URL. Зберігайте приклад помилки й результат повторного тесту, щоб команда бачила, що саме змінилося.

Наступний крок

  • Перевіряти товарні шаблони
