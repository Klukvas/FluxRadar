Як перевірити сайт, який рендерить контент JavaScript

Вихідний HTML і DOM після виконання скриптів: налаштування рендерингу, обмеження та контроль SEO-сигналів.

Опубліковано й перевірено: 20 жовтня 2026

У JavaScript-сайту можуть бути два різні представлення: початковий HTML сервера та сторінка після виконання скриптів. Аудит має явно показувати, яке з них було прочитано. Порожня оболонка застосунку не є достатнім доказом відсутності контенту після рендерингу.

У цьому матеріалі

  • Зіставте два представлення
  • Налаштуйте режим перевірки
  • Врахуйте обмеження публічного читання
  • Приклад із каталогом
  • Якщо DOM неповний

Зіставте два представлення

Відкрийте важливу сторінку й перегляньте вихідний код. Чи є там основний текст, title, canonical та посилання? Потім знайдіть ці самі елементи в DOM через інструменти браузера. Запишіть відмінності. Вони допоможуть зрозуміти, які сигнали додають скрипти.

Перевірте сторінку без входу та без збереженої згоди. Особистий браузер може мати кеш, cookies і доступ до даних, яких публічний краулер не отримує.

Налаштуйте режим перевірки

  1. Відкрийте «Перевірка» та виберіть потрібний профіль і пакет.
  2. Перегляньте параметр читання сторінок після виконання JavaScript.
  3. Для SPA залиште рендеринг увімкненим і задайте керовану область.
  4. Додайте важливі маршрути до «Початкові URL», якщо вони погано повʼязані навігацією.
  5. Після запуску прочитайте повідомлення про доступність браузерного середовища.

Якщо середовище не має підтримки рендерингу, звіт має повідомити це. Не називайте статичний HTML відрендереною сторінкою у власному висновку.

Врахуйте обмеження публічного читання

FluxRadar не відтворює повний особистий сеанс користувача: читання відбувається без cookies, завантажень і сокетів, із дозволеними GET/HEAD запитами та контролем публічних адрес. Контент, що зʼявляється після авторизованого POST-запиту, може бути недоступний у такій перевірці.

Також автоматичний рендеринг не дорівнює взаємодії людини з кожною вкладкою. Якщо важливі відомості зʼявляються лише після натискання, перевірте їх окремим ручним сценарієм і переконайтеся, що основний контент має доступне представлення.

Приклад із каталогом

Сервер повертає тільки <div id="root"></div>, а картки товарів зʼявляються після скрипту. Порівняйте звіт із рендерингом і фактичний DOM. Перевірте, чи посилання карток мають справжні href, чи canonical відповідає маршруту та чи сервер правильно відповідає на пряме відкриття URL.

Очікуваний результат — конкретні докази відрендереного контенту й пояснення того, що залишилося недоступним. Для перевірки представлення Google використайте URL Inspection у Search Console за наявності доступу.

Якщо DOM неповний

Перевірте помилки скриптів, API-відповіді, блокування ресурсів та залежність від географії. Не збільшуйте глибину обходу, якщо причина — порожній шаблон або недоступний API. Після виправлення повторіть контроль того самого маршруту і порівняйте початковий HTML та DOM.
