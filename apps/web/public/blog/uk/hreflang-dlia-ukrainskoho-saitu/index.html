Hreflang для українського сайту: без плутанини мов

Як пов’язати українські та інші мовні сторінки: відповідники, коди мов, зворотні посилання, canonical і перевірка шаблонів.

Опубліковано й перевірено: 14 жовтня 2026

Hreflang допомагає пошуковій системі зрозуміти, які сторінки є мовними або регіональними відповідниками. Він не перекладає матеріал і не робить слабкий переклад корисним. Для українського сайту найважливіше правильно зіставити зміст: сторінка послуги українською має відповідати тій самій послузі іншою мовою, а не будь-якій адресі з потрібним префіксом.

У цьому матеріалі

  • Визначте реальні мовні відповідники
  • Оберіть правильні коди
  • Забезпечте повну групу посилань
  • Узгодьте hreflang із canonical
  • Перевірте не лише головну

Визначте реальні мовні відповідники

Складіть таблицю: тема, український URL, інші версії, статус публікації. Якщо перекладу немає, не додавайте вигаданий відповідник на головну. Група має описувати наявні сторінки зі співвідносним основним змістом. Перевірте також, чи людина може перейти між ними через зрозуміле перемикання мови.

Навчальний приклад: /uk/posluhy/remont і /en/services/repair утворюють пару. Англійський блог про ремонт не є відповідником сторінки замовлення послуги. Порівнюйте призначення, а не лише схожість слів або наявність мови в адресі.

Оберіть правильні коди

Код української мови — uk. ua позначає країну в іншому контексті й не замінює код мови у hreflang. Якщо одна українська версія призначена для всіх читачів цією мовою, uk достатньо. Регіональне уточнення uk-UA доречне, коли справді потрібно описати конкретну аудиторію.

Не додавайте регіональні варіанти лише заради кількості тегів. Коли ціни, доставка чи юридичні умови різняться за країною, окремі сторінки можуть мати реальну підставу. x-default можна використати для сторінки вибору або запасного варіанта, якщо він відповідає вашому маршруту користувача.

Забезпечте повну групу посилань

Кожна сторінка групи повинна посилатися на себе й на відповідники; між версіями потрібні зворотні посилання. Використовуйте абсолютні адреси та перевіряйте кінцеві URL. Вказівка на перенаправлення або недоступну сторінку створює зайву неоднозначність.

Погодьте єдиний спосіб підтримки: HTML, sitemap або HTTP-заголовки для відповідних ресурсів. Google підтримує різні способи, але кілька паралельних механізмів збільшують ризик розбіжностей у CMS. Найзручніший для вашої команди спосіб має бути перевірюваним і стабільним після редагування.

Узгодьте hreflang із canonical

Canonical і hreflang виконують різні завдання. Перший повідомляє про основну версію серед дублів, другий — про мовні відповідники. Для повноцінних перекладених сторінок зазвичай потрібні основні адреси в межах відповідної мови, а не canonical усіх мов на одну українську головну.

Перевірте, що кожний відповідник відкривається, дозволений до індексації та містить очікувану мову. Сам атрибут lang допомагає описати документ для браузерів і допоміжних технологій, але не замінює налаштування мовних відповідників у пошуку.

Перевірте не лише головну

Візьміть послугу, товар, статтю та сторінку без перекладу. Перевірте групи до й після зміни шаблону. Найпоширеніше приховане рішення CMS — зберігати правильні пари на головній, але вести всі глибокі сторінки на корінь іншої мови.

  • Коди мов правильні й відповідають аудиторії.
  • У групі немає недоступних або вигаданих перекладів.
  • Сторінки містять себе й зворотні відповідники.
  • Canonical не суперечить мовному задуму.
  • Перемикання мови зберігає тему сторінки.

Після правки спостерігайте за даними Search Console. Коректна розмітка допомагає інтерпретації, але не гарантує конкретної позиції чи відображення вибраної версії для кожного запиту.
