Website images: alt text, formats and lazy loading

Four decisions for every image: what goes in the alt text, which format to serve, which dimensions to declare and when the file should load.

Published and checked: November 23, 2026

Images sell the product, explain the service and show the people behind a business. They are also what most often makes a page heavy, pushes text around while it loads and stays meaningless to visitors who listen to a site instead of looking at it. Most of these problems are solved in the page template and in the editorial routine, not with an expensive rebuild. Here is what to check on your own site and which parts belong to a developer.

Alt text is written for people, not for search

The alt attribute is the text that stands in for an image when the image cannot be seen. Screen readers read it out, browsers show it when the file fails to load, and search engines use it. Google calls alt text the most important attribute for giving more information about an image. In the same guide, Google warns against filling alt attributes with keywords: it hurts the user experience and may be treated as spam.

So start with one question: what would a person miss if they could not see this image? The answer is your alt text. If they would miss nothing, because the image is only decoration, the alt text should be empty.

On a product page, for example, the photo shows colour and shape, so alt text such as "Black backpack with two side pockets" tells a shopper what they would otherwise see. The same backpack in a decorative collage in the site header adds nothing new, and an empty alt fits there.

Five kinds of image and what to do with each

The W3C accessibility tutorials offer a decision tree for alt text. In short:

Kind Example What the alt text says
Informative product photo, map to the office a short description of the meaning the image carries
Functional icon link, magnifier search button where the link goes or what the button does: "Search", not "magnifier"
Decorative background pattern, divider an empty attribute, alt=""
Image of text banner with an offer headline the same text, unless it already appears nearby as real text
Complex chart, infographic a short description, with the full data in the page text

An empty alt and a missing alt are not the same thing. An empty alt="" tells assistive technology that the image is decoration and can be skipped. With no attribute at all, nobody can tell whether the image is decorative or someone simply forgot to describe it.

Writing alt text in practice

  • Describe what matters on this page. The same photo on a product page and in a care guide may need different descriptions.
  • Be specific. In Google's own example, "puppy" is better than nothing, and "Dalmatian puppy playing fetch" is best.
  • Do not list keywords. A comma-separated keyword list helps neither people nor search.
  • Check catalogue templates. If every product photo gets the same alt text from the product name, make sure it really describes each photo, not just the first.
  • Give files clear names. Google suggests short descriptive names such as my-new-black-kitten.jpg rather than IMG00023.JPG. It is a light signal, but it costs nothing.

One rule is usually enough for an editorial team: whoever uploads the image writes the alt text. A clean-up pass six months later tends to produce generic descriptions that help no one.

Formats and responsive versions

Google Search supports images in BMP, GIF, JPEG, PNG, WebP, SVG and AVIF when they are referenced in the src attribute of an img element. Google also recommends that the file extension matches the actual file type.

Choosing a format is a trade-off between file size, visual quality and what your CMS and hosting support. Do not rely on general promises of savings: convert a few of your own typical images and compare the file size and how they look on screen. For logos and simple icons SVG is often convenient: it is a vector format, so the image stays sharp on any screen. It is not suited to photographs. Separately, check whether the site sends photos that are several times larger than the size they are shown at.

To serve different versions for different screens, sites use the srcset attribute or the picture element. Google notes that some browsers and crawlers do not understand them, so always provide a fallback address in the src attribute.

Dimensions and lazy loading

When the browser does not know an image's size in advance, it shows the text first and then pushes it down once the image arrives. A visitor aims for a button and taps something else. web.dev recommends adding width and height attributes to every img element so the browser can reserve the space. This shift is what the CLS metric measures, covered in our article on Core Web Vitals.

The loading="lazy" attribute defers an image until the visitor scrolls close to it. On long pages with dozens of photos that helps. But web.dev explicitly advises against lazy-loading images that are likely to be visible when the page loads, especially the LCP image: the browser cannot start a lazy load until it knows where the image sits on the page. The main photo at the top of a page is often the largest element a visitor sees.

  • Hero image at the top of the page: no loading="lazy".
  • Images further down: loading="lazy" is fine.
  • Every image: width and height.

What FluxRadar checks, and what it does not

An automated check is good at finding technical gaps, but it does not judge meaning. On the pages its crawl reaches, FluxRadar checks:

  • Images without an alt attribute. FluxRadar finds img elements that have no alt attribute at all, and reports how many there are and the first one. An empty alt="" is treated as correct for decorative images. The finding appears under both SEO and accessibility, because it concerns both, and the report marks that the two share the same evidence.
  • Broken images and media. Images, video or audio for which the crawl has proof of failure: a 4xx or 5xx response, or an HTML page where a file was expected. Anything the crawl did not check is not reported as broken.

FluxRadar does not grade the quality of alt text, file formats, width and height attributes or lazy loading. Review those by hand in the template code or in the browser's developer tools, starting with the home page and your most visited product or service pages.

A practical order of work: first add alt text where it is missing entirely and fix broken files, because those show up in the report. Then agree with your developer on width, height and correct lazy loading in the template. A repeat check of the same sample of pages will show what changed.
